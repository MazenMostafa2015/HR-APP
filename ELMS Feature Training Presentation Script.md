# ELMS Feature Training Presentation Script

## Employee ID and Arabic Localization

**Audience:** HR administrators, system administrators, managers, and employees  
**Suggested duration:** 10–12 minutes  
**Format:** 8-slide presenter-led demonstration

---

## Slide 1 — What is new?

**On-screen title:** Employee ID and Arabic language support

**Presenter script:**

“Today we will review two new ELMS features. First, HR and administrators can assign a unique Employee ID to every person in the directory. Second, users can switch the desktop application and the main HR workspace between English and Arabic. The language preference is saved on the employee’s computer, so it remains selected the next time ELMS is opened.”

**Key message:**

- Employee IDs improve identification and reporting.
- Arabic is available without changing the server or database.
- Existing leave requests, approvals, files, and permissions remain unchanged.

---

## Slide 2 — Employee ID: who manages it?

**On-screen title:** Employee IDs are managed by HR or an administrator

**Presenter script:**

“Employee IDs are maintained from the Administration area. Users with HR access can view the directory, while the administrator role can update employee profiles. The Employee ID is separate from the internal database user ID and from the employee’s email address. Use the official company identifier, such as `EMP-001`, `HR-2045`, or the format defined by your HR policy.”

**Demonstration steps:**

1. Sign in with an HR or administrator account.
2. Open **Administration** from the left navigation.
3. Locate the **People directory**.
4. Find the employee by name or email.

**Important note:** Employee ID values must be unique. Do not assign the same ID to two people.

---

## Slide 3 — Adding or changing an Employee ID

**On-screen title:** Save an Employee ID

**Presenter script:**

“In the People directory, the Employee ID column appears beside the employee’s name. Enter the official ID in the field, then review the role, department, manager, and active status before selecting the save button. The change is stored on the central ELMS server and is available to authorized HR and administrator users.”

**Demonstration steps:**

1. Click the Employee ID field.
2. Type the identifier, for example `EMP-001`.
3. Confirm the employee’s department and reporting manager.
4. Select the save icon.
5. Wait for the confirmation message: **User profile updated.**
6. Refresh the directory if necessary.

**Correction procedure:**

“If an ID was entered incorrectly, replace it with the correct value and save again. To remove an ID, clear the field and save. If the system reports a duplicate, check the directory for the employee currently using that identifier.”

---

## Slide 4 — Employee ID operational guidance

**On-screen title:** Use the ID consistently

**Presenter script:**

“Employee IDs should follow one company-wide format. HR should decide whether leading zeros, department prefixes, or legacy IDs are preserved. Avoid putting confidential information inside the ID. An ID should identify the employee; it should not contain a password, national identification number, or other sensitive value.”

**Recommended controls:**

- Assign one ID per employee.
- Do not recycle an ID for another person unless company policy explicitly allows it.
- Keep the ID consistent with payroll and HR records.
- Check the ID before exporting reports or correcting a profile.
- Restrict profile editing to authorized administrators.

---

## Slide 5 — Choosing Arabic in the desktop app

**On-screen title:** Select العربية from the desktop setup screen

**Presenter script:**

“On first launch, the desktop application displays the server connection screen. The language button appears in the upper-right area. Select **العربية** to switch the setup instructions to Arabic. Enter the internal ELMS server URL provided by IT, then select **فتح ELMS**.”

**Demonstration steps:**

1. Open ELMS Desktop.
2. Select **العربية**.
3. Confirm that the setup instructions and labels change to Arabic.
4. Enter the internal server address.
5. Select **فتح ELMS**.
6. Complete company sign-in.

**Security reminder:**

“Use the approved internal HTTPS address. Do not enter a public or untrusted server address.”

---

## Slide 6 — Switching language inside ELMS

**On-screen title:** Change between English and Arabic at any time

**Presenter script:**

“After signing in, the language button remains available in the top bar. In English mode it displays **العربية**. Select it to switch to Arabic. In Arabic mode it displays **English**. The application changes the main navigation, dashboard labels, request pages, forms, reports, approval dialogs, statuses, and supporting messages. The page direction also changes to right-to-left for Arabic.”

**Demonstration steps:**

1. Open the top-bar language button.
2. Select **العربية**.
3. Open **طلبات الاعتماد** or **طلباتي**.
4. Open **طلب جديد** to demonstrate the Arabic form.
5. Switch back to **English** and confirm the same request data remains unchanged.

**Key message:** The language change affects presentation only. It does not translate or modify stored employee names, leave reasons, uploaded files, or database records.

---

## Slide 7 — Using the Arabic leave request form

**On-screen title:** Submit a request in Arabic

**Presenter script:**

“The Arabic form follows the same workflow as the English form. Select the leave type, start date, end date, and any half-day options. The total days are calculated automatically. Add the reason in the notes field, attach a PDF, JPG, or PNG when required, and select **إرسال للمراجعة**.”

**Demonstration steps:**

1. Select **طلب جديد**.
2. Choose **نوع الإجازة**.
3. Enter **تاريخ البداية** and **تاريخ النهاية**.
4. Review **إجمالي الأيام**.
5. Enter **السبب / الملاحظات**.
6. Add a supporting document if the policy requires it.
7. Select **إرسال للمراجعة**.
8. Confirm that the request moves to the **المدير المباشر**.

**Workflow reminder:**

“The approval path is still Direct Manager, General Manager, then HR. Arabic changes the labels, not the approval rules.”

---

## Slide 8 — Support, rollout, and final checklist

**On-screen title:** Rollout checklist

**Presenter script:**

“For rollout, HR should assign and verify Employee IDs before users begin relying on reports. IT should distribute the latest desktop installer and provide the correct internal server URL. Employees should select their preferred language during setup or from the top bar after signing in.”

**Final checklist:**

- [ ] Every active employee has the correct unique Employee ID.
- [ ] HR and administrators know where to edit the ID.
- [ ] Employees have the current desktop installer.
- [ ] The internal HTTPS server URL is documented.
- [ ] Arabic and English labels display correctly.
- [ ] A test request has been submitted in Arabic.
- [ ] The request can be reviewed and approved by the normal workflow.
- [ ] The user can switch back to English without losing data.

**Closing script:**

“Employee ID gives HR a reliable business identifier, while Arabic localization makes the same controlled workflow easier to use for Arabic-speaking employees and managers. Both features are available without creating a second database or a separate application.”
